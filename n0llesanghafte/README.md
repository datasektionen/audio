# n0llesånghäfte

Typst project for generating the reception song booklets as PDFs.

Six variants are produced, differing in front pages:
- nØllan
- dOsq
- Storasyskon
- Toast
- blank (for when nØllan inevitably lose their song booklet and we have to print new ones with a different message on)


## Prerequisites

- [Typst](https://typst.app/) — the `typst` CLI must be on your `PATH`
- `python3` and `jq` — used by the build script to maintain the personalen image manifest

## Building

Run the build script from anywhere:

```bash
./build_pdfs.sh
```

This will:

1. Regenerate `data/personalen images/manifest.json` from the images currently in that folder.
2. Copy `../songs.json` into the project root so Typst can access it within its sandbox.
3. Compile all five variants to `export/`.

Output PDFs land in `export/`:

| File | Intended for |
|---|---|
| `blank.pdf` | Generic / unmarked copy |
| `dosq.pdf` | dOsq |
| `nollan.pdf` | n0llan |
| `storasyskon.pdf` | Storasyskon |
| `toast.pdf` | Toast |

## Project structure

```
n0llesanghafte/
├── build_pdfs.sh          # Build script — run this to produce PDFs
├── songs.json             # Copy of ../songs.json — refreshed on every build.
│                          # Kept between builds so `typst preview` works without
│                          # running the full build script first. Not committed.
├── template.typ           # Page layout, song-book show rule, song() function
├── text-content.typ       # Parser for the song text format (HTML tags, line breaks)
├── arskursnamn.typ        # Renders the year-class name table
├── gender-marker.typ      # Gender marker helper
│
├── blank.typ              # Entry point: blank variant
├── dosq.typ               # Entry point: dOsq variant
├── nollan.typ             # Entry point: n0llan variant
├── storasyskon.typ        # Entry point: storasyskon variant
├── toast.typ              # Entry point: toast variant
│
├── content/               # Shared page content (included by all variants)
│   ├── content.typ        # Top-level include order for all content pages
│   ├── mottagningsinfo.typ # Reception info + Daddetitel phone list
│   ├── songs.typ          # All song pages with layout and decorative images
│   ├── personalen.typ     # Personalen photo grid
│   ├── last-page.typ      # Back cover with optional sponsor logo
│   ├── page-padding.typ   # Adds blank pages to keep total count divisible by 4
│   ├── title-page-blank.typ
│   ├── title-page-dosq.typ
│   ├── title-page-nollan.typ
│   ├── title-page-storasyskon.typ
│   └── title-page-toast.typ
│
├── data/                  # Year-specific data — update these each year
│   ├── meta.json          # Current year, year-class names, branch config
│   ├── personalen.json    # Personnel list (name, KTH username, title, branch, n0llegroup)
│   ├── personalen images/ # Portrait photos
│   │   ├── manifest.json  # Auto-generated by build_pdfs.sh — do not edit manually
│   │   └── placeholder.jpg # For when someone in the staff does not have a picture taken
│   ├── titel images/
│   │   ├── titel.jpg      # Group photo of Titel
│   │   └── titel.json     # Layout config for the Titel page
│   └── spons/             # Sponsor assets (example: voi.svg)
│
├── resources/             # Static assets used across all variants
│   ├── background.pdf     # Page background
│   ├── last-page.pdf      # Back cover artwork
│   └── *.png              # Decorative illustrations used in songs.typ
│
└── export/                # Build output — generated, not committed
```

## Updating for a new year

1. Set `current_year` in `data/meta.json`.
2. Add the new year-class entry to the `years` map in `data/meta.json`.
3. Replace `data/personalen.json` with the current year's personnel export.
4. Drop portrait photos into `data/personalen images/` — filenames must match the KTH usernames used in `personalen.json`. The manifest is rebuilt automatically on each build.
5. Update `data/titel images/titel.jpg` and `titel.json` for the new Titel group photo.
6. Run `./build_pdfs.sh`.
